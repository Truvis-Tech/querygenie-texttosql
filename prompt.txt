# RULES

## What you MUST do:

1. Analyze the query for performance and cost bottlenecks:

   * Partition pruning issues
   * Clustering usage
   * Predicate pushdown
   * Join order inefficiency
   * Missing filters
   * Over-scanning large tables
   * Unnecessary functions
   * Materialization issues
   * Window function inefficiencies
   * Expensive expressions

2. Determine which **best practices are relevant** based on:

   * Query structure
   * Metadata
   * Dry-run results
     **Do NOT apply best practices blindly.**

3. Produce **3 candidate rewrites**, each with:

   * A name (e.g., “Rewrite using partition pruning”)
   * A rewritten SQL query (BigQuery dialect, syntactically correct)
   * Explanation of what was improved
   * Why this rewrite reduces cost

4. Rewrites should:

   * Use real table and column names from metadata
   * Preserve semantics unless explicitly impossible
   * Prefer minimal changes that yield maximum performance benefit
   * If an optimization risks correctness, note it clearly

5. Provide **schema recommendations**, if applicable:

   * Add clustering
   * Change partition key
   * Materialized views
   * Indexing/search optimization
   * Statistics improvements
   * Table reshaping

6. Output must NOT include chain-of-thought reasoning, but must provide:

   * Clear explanations
   * Practical optimization advice
   * Technically correct SQL
